# F&O Monthly Expiry-Day Effect — Gut-Check Methodology, Pre-Committed 2026-07-26 Before Any Result Exists

## Why this exists

The second of two real, academically-backed strategy candidates found in the
2026-07-25 web research pass (see `docs/PAIRS_TRADING_METHODOLOGY.md`'s
intro for the other one, cointegrated pairs trading — now closed, FAILED
its pooled bar, see `docs/PAIRS_TRADING_RESULTS.md`). A 22-year academic
study found a genuine last-Thursday-of-month volatility/price-dislocation
pattern around NSE derivatives expiry (arxiv 2507.04859), and broader
option-market research attributes predictable expiry-window returns to
order-imbalance from position unwinding overwhelming market-maker
risk-bearing capacity.

This is candidate 13 in this project's search (see
`quantos_three_strategy_proposals_review` and
`quantos_momentum_turnover_ablation_status` memories for the running count
and prior-failure context).

**Do not edit this file after the gut-check has run.** A wrong parameter is
a finding for a NEXT pre-registered run, not a retroactive edit here.

## Scope: a gut-check, not a backtest — deliberately, per project precedent

Every prior candidate that reached a full pre-registered backtest started
with a cheap, descriptive gut-check first (PEAD:
`core/fundamentals/pead/gutcheck.py`, index reconstitution:
`core/rotation/reconstitution_gutcheck.py`) — group-mean comparisons, no
transaction costs, no position sizing, no Sharpe/profit-factor, no signal
threshold. This doc follows that same sequencing: establish whether NIFTY
actually behaves differently around expiry before designing a tradeable
strategy and its cost model around a pattern that might not be there.

## Expiry-date construction — sourced, not assumed, and genuinely time-varying

NSE's monthly expiry weekday changed mid-way through this project's usable
data window — confirmed live 2026-07-26, not assumed from memory:

- **Last Thursday of the month**, for any expiry falling on or before
  2025-08-31 (existing convention, unchanged for contracts maturing in
  that range).
- **Last Tuesday of the month**, from 2025-09-01 onward — per SEBI
  circular SEBI/HO/MRD/TPD-1/P/CIR/2025/76 (26 May 2025) and NSE's own
  implementation circular, corroborated by Zerodha's and ICICI Direct's
  contemporaneous coverage. (An earlier March-2025 announcement proposed
  Monday expiry; this was superseded before ever taking effect — a real
  wrinkle, noted so a future session doesn't rediscover it as a surprise.)
- **Holiday adjustment**: if the calculated last-Thursday/last-Tuesday is
  not an actual NSE trading day, the expiry rolls to the nearest EARLIER
  trading day. Detected empirically against the real cached trading-day
  calendar (a date with no bhavcopy row is treated as non-trading, same
  "attempt the fetch, 404 means not a trading day" pattern
  `core/options/vrp/bhavcopy.py` already uses) — **no hardcoded NSE
  holiday calendar is built**, same precedent as every prior bhavcopy-based
  script in this project.

## Data source — reused, not re-fetched

**NIFTY spot (`underlying_close`) from the already-cached NSE F&O bhavcopy**
(`core/options/vrp/bhavcopy.py`'s raw zip cache, `data_cache/nse_bhavcopy/raw/`)
— the exact same source and field `docs/VOL_SPREAD_METHODOLOGY.md` and
`docs/VOL_SKEW_METHODOLOGY.md` already used for NIFTY spot. Restricted to
**2024-01-01 onward** (new bhavcopy format only — `underlying_close` is not
populated in the legacy schema, same cutover rule every prior candidate
using this field has already applied). No live Fyers/broker token needed —
same advantage `docs/VOL_SKEW_METHODOLOGY.md` flagged, deliberately chosen
over the longer 5-year Fyers-fetched series `docs/VOL_SPREAD_VALIDATION.md`
used, since that run blocked on an expired token requiring interactive
OAuth (`feedback_interactive_scripts`).

**Disclosed limitation, stated up front**: ~2.5 years of data yields only
~30 monthly expiries — a real, thin sample for a monthly-cadence effect,
smaller than the 22-year academic study's own window by an order of
magnitude. This gut-check reads as a directional sanity check against that
literature, not an independent confirmation at comparable statistical
power. If the gut-check result is promising enough to justify a full
backtest, sourcing a longer NIFTY spot history (the Fyers-fetched path, or
another free source) becomes a real next-step decision, not a silent
assumption.

## Day-groups compared

For every trading day `t` in the window with a defined `underlying_close`:

- **`expiry`**: `t` is itself an expiry day (per the construction above).
- **`pre_expiry`**: `t` is the trading day immediately before an expiry day.
- **`post_expiry`**: `t` is the trading day immediately after an expiry day.
- **`other`**: every remaining day (the baseline).

A day can only belong to ONE group — if a holiday-adjusted expiry lands
such that pre/post/expiry would otherwise overlap for an unusually short
month, `expiry` takes priority over `pre_expiry`/`post_expiry`, which in
turn take priority over `other`. Logged if it ever actually happens, not
assumed impossible.

## Metrics — descriptive only, matching this project's gut-check style

For each group: **n, mean daily return (%), mean |daily return| (%)**
(a realized-volatility proxy — the literature's actual claim is about
volatility/dislocation, not directional bias, so this is the primary
metric, not the mean return). Daily return = `close_t / close_{t-1} - 1`,
using the SAME `underlying_close` series throughout (no mixing with a
separately-fetched series, same "one data source" rule every prior
candidate has followed).

No demeaning, no market adjustment, no invented significance test — plain
group means and counts, same zero-invented-significance-test style as
`docs/REGIME_VALIDATION.md`, `docs/VOL_SPREAD_VALIDATION.md`, and
`docs/VOL_SKEW_VALIDATION.md`.

## What would make this gut-check untrustworthy after the fact

- Changing the expiry-weekday schedule, the holiday-adjustment rule, or
  the day-group boundaries (pre/post = exactly 1 trading day each) after
  seeing a weak or strong result.
- Treating a thin/noisy `expiry` group mean as decisive without reading it
  against `n` (~30 expiries in this window) and the disclosed short-window
  limitation.
- Skipping straight to a full backtest (position sizing, entry/exit rules,
  a new cost model) without this gut-check first, or building one around a
  gut-check result that turns out flat.
- Connecting this to any other candidate's trade data (pairs trading,
  VRP, the Iron-Condor CSV) before this gut-check's own read is locked —
  same mandatory-sequencing discipline as every prior vol-related
  candidate in this project.

## Pass/fail bar

Not a P&L bar — a descriptive read, same category as the reconstitution
and PEAD gut-checks. **"Worth a full backtest" reads as**: `expiry` and/or
`pre_expiry`/`post_expiry` mean |daily return| visibly and consistently
exceeds the `other` baseline, by a margin that isn't trivially explained by
the small `n` (~30) of the expiry group. A flat or noisy result closes this
thread at the gut-check stage, the same way PEAD's inconclusive gut-check
kept it from ever reaching a full pre-registered backtest — cheap to run,
cheap to walk away from.
