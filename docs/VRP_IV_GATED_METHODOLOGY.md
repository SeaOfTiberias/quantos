# IV-Gated Short Premium (Strangle / Straddle / Iron Condor) — Methodology, Pre-Committed 2026-10-06 Before Any Result Exists

Follow-up to docs/VRP_IV_CONDITIONAL_CHECK_RESULTS.md, the exploratory,
NOT pre-registered tercile cut of the VRP short-strangle trades. That
cut found high entry-IV trades did far better (PF 1.661, Sharpe 1.465)
than low entry-IV trades (PF 0.787, Sharpe -0.595), and listed what a
proper test would need: a trailing percentile instead of in-sample
terciles, a clustering check, and a capital-based result instead of
pooled %-of-credit stats. This doc fixes all of that, and every other
design choice, before any code for it is written or run.

**Do not edit this file after the backtest has run.** A parameter that
turns out wrong is a finding for a NEXT pre-registered run, not a
retroactive edit to this one.

## Why this is a fair test and not a re-run of the same data

The exploratory pattern was found in 2023-07-24..2026-07-22. Re-testing
on that window would only confirm what was already seen. So the verdict
is taken **only on data that has never been looked at for this
question**: 2019-02-11 (NIFTY weekly options launch) to 2023-07-21.
That window is fetched for this run with the existing Phase 1 pipeline
(core/options/vrp/bhavcopy.py, legacy-schema archive), and contains
the 2020 COVID crash, the 2020-21 high-IV recovery, and the 2022 rate-hike
drawdown, so it is not calm-markets-only.

## Data

NSE daily F&O bhavcopy, NIFTY index options only, via
`scripts/fetch_vrp_bhavcopy.py`. Full window 2019-02-11 to 2026-10-05.
Three segments, fixed now:

| Segment | Entries | Role |
|---|---|---|
| Warm-up | first 40 cycles from 2019-02-11 | builds the IV history the gate needs; no trades counted |
| **A — fresh** | after warm-up, through 2023-07-21 | **the verdict** |
| B — seen | 2023-07-24 .. 2026-07-22 | where the exploratory pattern came from; reported only |
| C — new | 2026-07-23 .. 2026-10-05 | out-of-sample forward data; reported only (too few cycles to judge) |

## Entry cycles

Unchanged from docs/VRP_METHODOLOGY.md: roll immediately into the
nearest unexpired weekly the trading day after the prior cycle's
expiry (`core/options/vrp/strikes.py::build_entry_cycles`). Expiry
weekday is read from the data each cycle, never hardcoded. Fill at the
entry day's recorded `close`.

## The IV gate (the thing under test)

- **IV measure:** at-the-money IV on the entry day, for the cycle's own
  expiry. ATM strike = the listed strike nearest the put-call-parity
  forward (`strikes.py::synthetic_forward`) with both CE and PE priced.
  ATM IV = mean of the CE and PE IVs at that strike
  (`core/options/greeks.py::implied_volatility`). ATM, not the 0.20-delta
  legs the exploratory cut used: ATM IV is the same number whichever
  structure is traded, so all three arms share one gate.
- **Percentile:** fraction of the previous 52 cycles' ATM IVs (about one
  year of weekly cycles) that are strictly below today's. Only cycles
  before today count, so the gate never sees the future. Every cycle
  is entry-day-after-expiry, so all 52 comparison values sit at the same
  ~5-7 day DTE; comparing like with like.
- **Gate open:** percentile >= 0.67 (top third, matching the
  exploratory tercile split). Gate closed: no trade that cycle; capital
  sits idle and earns 0.
- **Warm-up:** the gate needs at least 40 prior cycles with a valid
  ATM IV. Before that, no trade in any arm.

## Structures (three arms, all sold at the same entry, held to expiry)

1. **Short strangle — PRIMARY.** Exactly docs/VRP_METHODOLOGY.md's
   legs: ~0.20-delta OTM call + put, 2% OTM fallback
   (`strikes.py::select_strangle`, unmodified). Primary because it is
   the structure the exploratory pattern was found on.
2. **Short straddle — secondary.** Sell CE + PE at the ATM strike
   defined above.
3. **Short iron condor — secondary.** The primary arm's two short legs,
   plus a long call and a long put at ~0.05 delta (tolerance 0.04),
   each strictly further OTM than its short leg. Fallback if no strike
   fits: the listed strike nearest 2% beyond the short strike. Defined
   risk; tests whether capping the tail keeps the edge.

No stop-loss, no profit target, no adjustment, no early close — same
as the original VRP test. Exit = cash settlement at the underlying's
final settlement value (`simulator.py::_underlying_settlement`,
unmodified), each leg at intrinsic value.

## Costs

Real NSE F&O charges, per leg, in index points (lot-size-invariant,
as established in core/options/vrp/costs.py). Two corrections to
that module, applied to THIS run only (the original VRP result stands
as published):

- **STT on selling options** by date: 0.05% of premium until
  2023-03-31, 0.0625% from 2023-04-01 (Union Budget 2023), 0.1% from
  2024-10-01, 0.15% from 2026-04-01. The original module applied
  0.0625% to all dates before 2024-10-01, which was right for its
  2023-07+ window but not for 2019-2023.
- **STT on exercise is paid by the option HOLDER**, not the writer:
  0.125% of intrinsic value (0.15% from 2026-04-01), charged on the
  iron condor's LONG legs if they finish in the money. Short legs pay
  no exercise STT. (The original module charged it to the short legs,
  which made that result very slightly too pessimistic.)
- **Exchange transaction charge**: 0.053% of premium before 2024-10-01
  (NSE's published top-slab options rate, conservative), 0.03503% from
  2024-10-01 (uniform rate). SEBI fee 0.0001%. GST 18% on brokerage +
  exchange + SEBI. Brokerage 0.03% capped at Rs20/order (cap
  non-binding at these premiums, see costs.py).
- **Stamp duty** 0.003% on bought premium (the condor's long legs only).
- A leg that expires OTM costs nothing at expiry.

## Capital and returns

Return per trade = NET P&L (points) / margin (points), where margin is:

- Strangle and straddle: **12% of the entry-day forward** — one side
  of NSE's SPAN + exposure margin for a NIFTY short option position,
  approximated as a fixed percentage. Because it is a fixed
  proportion of spot, it scales every trade by the same factor and does
  NOT change profit factor or Sharpe; it only sets the absolute return
  level.
- Iron condor: **the wider of the two wings' widths (points)**, gross of
  credit — the maximum the position can lose before credit, which is
  what NSE's hedge-benefit margin converges to for a defined-risk spread.

Weekly return series: one value per eligible cycle — the trade's
return-on-margin if the gate was open, **0 if it was closed**. Idle
weeks stay in the series; leaving them out would overstate Sharpe.

## Pass/fail bar (Segment A, NET, primary arm)

**PASS requires all four:**

1. **Edge:** profit factor > 1.0 AND Sharpe > 0.5 (annualized √52, on
   the zero-filled weekly return-on-margin series). Same bar as every
   other candidate in this project.
2. **The gate earns its place:** gated Sharpe > ungated Sharpe, where
   ungated = the same structure traded every eligible cycle in
   Segment A. A gate that doesn't beat always-on is not a finding.
3. **Not one episode:** no single calendar quarter supplies more than
   50% of the gated arm's total net P&L in Segment A. The number of
   distinct gate-open runs (consecutive open cycles) is also reported.
4. **Sample size:** at least 30 gated trades in Segment A. Fewer than
   that is **INCONCLUSIVE**, not a pass and not a fail.

Secondary arms are judged against the same four criteria and
reported. With three arms tested, one passing by chance is likelier
than with one; so a secondary arm passing while the primary fails is
recorded as **"secondary-only pass — needs its own pre-registered
confirmation on fresh data"**, not a validated edge.

## Also reported (not part of the verdict)

- Segments B and C, every arm, gated and ungated.
- Per-trade stats (win rate, %-of-credit P&L, profit factor), for
  comparison with the original VRP numbers.
- Worst single trade per arm, as % of margin, and max drawdown of the
  cumulative return-on-margin series.
- Count of strike fallbacks per leg, cycles skipped for missing data,
  and cycles where ATM IV could not be computed.
- Data integrity: on each expiry day, all rows for that expiry should
  carry one shared settlement value (the bhavcopy quirk documented in
  simulator.py). Any expiry where they disagree is counted and listed;
  it was only verified on 2023+ data before.

## What would make this result untrustworthy after the fact

- Changing the 0.67 threshold, the 52-cycle lookback, the 40-cycle
  warm-up, the wing delta, or the margin model after seeing a result.
- Promoting Segment B (seen data) or a secondary arm to the headline.
- Adding a stop-loss/profit target, an India VIX filter, or an event
  filter after seeing the hold-to-expiry result.
- Dropping the COVID-2020 crash, or any other stretch, from Segment A.

Any of those becomes a new, separately pre-registered run.

## Known limits, stated up front

- Fills at the recorded daily close; real fills cross a bid-ask spread
  this data doesn't show. Weekly 0.20-delta and ATM NIFTY options are
  among the most liquid contracts in the world, but the condor's
  0.05-delta wings are thinner.
- The gate reads that same close to decide; a live version would decide
  a few minutes before the close on a near-identical IV.
- Margin is a fixed-percentage proxy, not historical SPAN files.
- No interest earned on idle or posted margin.
