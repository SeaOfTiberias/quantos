## The source strategy

This is a **self-designed classic Opening Range Breakout**, not a strategy
the user brought from an external source (unlike candidates 14/15, which
were named retail day-trading ideas) — disclosed up front because it means
there is no independent "source material" to defer parameter choices to;
every parameter below is this document's own choice, made before seeing
any result.

**5-minute** NIFTY and BankNifty index candles (switched from 1-minute
2026-07-28 — see the Resolution note below "The central limitations"; a
1-minute retention wall on Fyers made the original design statistically
unusable). The **first 15 minutes of the session (09:15–09:30 IST, the
first three 5-minute candles)** form the opening range; that range's
`(high, low)` are the breakout levels. From the 4th 5-minute candle
(09:30–09:35) onward, on **candle close**: a close above the range high →
**CALL**; a close below the range low → **PUT**. First occurrence only —
**one trade per day**, matching candidate 15's precedent (chosen
explicitly over multi-trade re-entry, which is more exposed to the
per-trade spread cost that already broke candidate 15).

**NIFTY and BankNifty are tested independently, with separate reported
results — never pooled.** A pass on one and a fail on the other is a real,
reportable outcome, not something to average away.

## The central limitations, stated up front

### 1. Synthetic option premiums (inherited from candidate 15)

`docs/CANDIDATE15_OPTION_DATA_FEASIBILITY.md` confirmed 2026-07-27: **Fyers
has no historical intraday data for any expired option contract.** Every
premium value in this backtest is a Black-Scholes theoretical price from
the real index level + a real India VIX-derived IV input — not a real
traded/settled price. Real bid-ask spread, skew/smile deviation from
Black-Scholes fair value, and fill slippage are unmeasured. **This is the
exact limitation that closed candidate 15**: a real index-level edge (₹54/
trade) turned out to be smaller than a realistic option bid-ask spread.
Scalping means more round-trips per day than candidate 15's one-shot daily
breakout, so this cost-sensitivity risk is *worse* here, not better — the
cost model (below) must be applied before any pass/fail read, not as an
afterthought.

### 2. 1-minute historical depth — CONFIRMED LIVE 2026-07-28, and it is severe

`scripts/probe_1min_depth.py`, run live 2026-07-28: **Fyers retains only
~28-29 calendar days of 1-minute history, identically for NIFTY 50, NIFTY
BANK, and India VIX** — data present 28 days before the probe date
(2026-06-30), completely empty 30 days before (2026-06-25). This is a hard
rolling-retention wall, not a per-request chunk limit (unlike the ~100-day
*chunk* limit confirmed for 5m/60m in other scripts, which is a request-
size constraint, not a total-depth one) — every prior intraday candidate
(14, 15, expiry-day) used 5-minute-or-coarser data with multi-year depth
(candidate 15's 5m BankNifty/VIX confirmed back to 2021-05); nothing in
this project has ever hit a constraint this tight before.

**Consequence**: a 1-minute backtest window is really only ~20 trading
days. At one trade per day *only on days that actually breach the opening
range*, this yields on the order of **10-15 trades per index** for the
entire test — not a "smaller than usual" sample, but too small to compute
a meaningful profit factor or Sharpe ratio at all, and it necessarily
covers a single month of one volatility regime rather than a
representative cross-section of market conditions. This is a harder
version of the small-sample problem that shelved the PEAD candidate
(`quantos_pead_earnings_feasibility` memory) and is a materially different
situation from every strategy this project has actually backtested to a
verdict. **The backtest window and go/no-go path forward were re-decided
by the user after this finding — see the "Resolution" note immediately
below** before reading anything past this point as still in force.

### Resolution (2026-07-28): switched to 5-minute candles

User's explicit choice, presented with three options (switch resolution,
run 1-minute anyway as a disclosed non-verdict gut-check, or close the
candidate now as infeasible): **switch the whole candidate to 5-minute
candles**, trading strict "scalping" cadence for a real, statistically
usable sample by reusing the multi-year 5-minute depth already confirmed
live for NIFTY (candidate 14, back to 2022-05-28) and BankNifty/VIX
(candidate 15, back to 2021-05). **Every section below this point has
been rewritten for 5-minute candles** — no 1-minute reference past this
point is still in force; the 1-minute design above is preserved only as a
record of what was probed and why it was abandoned, not as a fallback.

## Contract selection

- **BankNifty**: nearest monthly contract (candidate 15's precedent).
- **NIFTY**: nearest **weekly** contract (NIFTY still trades weeklies,
  unlike BankNifty) — a disclosed asymmetry between the two symbols'
  contract selection, not an inconsistency; each uses its own real market
  structure. **DTE floor (added 2026-07-28, before any backtest ran)**: if
  the trade's own entry date has `days_to_expiry < 2` on the nearest weekly
  contract, roll selection to the **next** weekly contract instead. This
  directly closes the "weaker justification" gap flagged below under
  Premium reconstruction — the undiscounted-theta assumption is only
  defensible with at least a couple of days of remaining life. BankNifty's
  monthly contracts never trigger this (always well clear of 2 DTE), so
  the rule is NIFTY-only, applied uniformly across the whole window (not
  conditionally invoked only where it happens to help).
- **Strike**: nearest-strike ATM at the moment of entry, for both indices
  — fixed at entry, never re-struck if price runs (same as candidate 15).
  Strike interval and lot size: BankNifty confirmed (100pt / lot 30, from
  candidate 15); **NIFTY confirmed live 2026-07-28** via
  `core/options/fyers_symbol_master.py`'s `get_lot_size("NIFTY")` and a
  distinct-strikes scan of the live NSE_FO master — **lot size 65**
  (matches the module's own docstring note that SEBI changed it 75→65 in
  Jan 2026) and **near-the-money strike interval 50 points** (wider gaps
  appear further OTM, as expected — 50pt is the ATM-region spacing this
  backtest actually uses).

## Session definition

Regular NSE session, 09:15–15:30 IST. **Flatten any open position by 15:20
IST** — same square-off buffer as candidates 14/15.

## Reference range and breakout signal

- **Opening range**: the high/low across the first **three 5-minute
  candles** of the session (09:15–09:20, 09:20–09:25, 09:25–09:30).
  Unavailable (no signal possible) on any day with fewer than 3 candles
  before 09:30 (e.g. a shortened session) — skipped, not approximated.
- From the 4th 5-minute candle (09:30–09:35) onward, **on candle close**
  (not intrabar wick touch — same no-intrabar-noise discipline as every
  prior candidate):
  - `close > range.high` → **CALL** signal (first occurrence only).
  - `close < range.low` → **PUT** signal (first occurrence only).
  - Whichever fires first is the day's only trade. A day with neither
    breakout by 15:20 IST has no trade.
- **Execution**: at the **open of the next 5-minute candle** after the
  signal candle's close — no same-bar execution.

## Exit management — broker-side trailing stop, no fixed target

User's explicit choice: reuse the broker-side pattern (`agent/main.py`'s
Task 4 `auto_exit` for equities — a real, separate Fyers SL_M order that
survives agent death, ratcheted by the agent's polling loop) rather than a
TradingView-driven exit alert. This is a **different exit mechanic than
candidate 15** (which used a fixed 200pt target) and than the existing
`/webhook/options` human-triggered flow (which deliberately puts trailing
logic in Pine specifically to avoid agent-side trailing complexity) —
disclosed as a deliberate divergence, made because the user found
broker-side management more robust for this build, not an oversight.

- **Initial stop**: opposite side of the opening range at entry — CALL:
  `stop = range.low`; PUT: `stop = range.high`. Placed on the **index
  level** (translated to an option-premium stop via the same Black-Scholes
  reconstruction used for entry/exit pricing, not a raw premium stop) —
  classic ORB stop placement, not capped/scaled the way candidate 15's
  named source material capped its stop at 40pt (there is no source
  material here to defer to).
- **Trailing**: once price has moved in the trade's favor by one **range
  width** (`range.high - range.low`) from entry, the stop trails to the
  low (CALL) / high (PUT) of the prior **3 five-minute candles** (15
  minutes — re-picked 2026-07-28 for the 5m switch; not a mechanical
  rescale of the original 1-minute "prior 5 candles" lookback, since a
  literal 5x5m=25-minute window would trail noticeably looser than the
  original 5-minute lookback's character — 3 candles was chosen fresh as
  the closest same-order-of-magnitude short-swing window), recomputed on
  every new candle close, **only ever moving in the favorable direction**
  (never loosens) — a new, disclosed, purely mechanical rule (not a reuse
  of `core/darvas/box.py`'s `next_trailing_stop`, which trails to Darvas
  box geometry that doesn't apply to an index breakout).
- **No fixed profit target** — matches the user's own framing ("manage the
  trade until trail closure or stop loss"); the trade runs until the
  trailing stop is hit or the 15:20 IST session flatten, whichever first.
  Confirmed 2026-07-28: kept as trail-to-run, not switched to a
  scale-out-at-1R design (a real alternative considered and declined —
  scale-out reduces giveback on winners but caps the upside that a pure
  trailing system exists to capture; the user's explicit choice, not a
  default).
- **Secondary hard premium stop (added 2026-07-28, before any backtest
  ran)**: alongside the index-level stop above, the position is also
  closed if the reconstructed option premium itself falls **25% below its
  entry premium**, whichever of the two stops triggers first. This is an
  OR condition, not a replacement — it exists because the index-level
  stop cannot see IV crush or vega/theta decay from a slow reversal that
  never actually hits the index-level stop; the premium itself can still
  collapse well before that happens. **25% is this document's own choice,
  not derived from any data** — subject to the same
  "no changes after the backtest runs" rule as every other parameter here.

## Premium reconstruction

Same method as candidate 15: `compute_greeks(spot=<index level>,
strike=ATM, days_to_expiry=(expiry - trade_date).days, implied_vol=<VIX 5m
close at that candle's own timestamp>/100, option_type=CALL_or_PUT
).theoretical_price`, evaluated at entry, at every trailing-stop
recomputation, and at exit — using the **contemporaneous** VIX reading
each time (not frozen at entry), same rationale as candidate 15.
Intraday theta between entry and exit is not modeled (same disclosed
limitation, same justification: trades open and close same-session,
theta over minutes-to-hours is small relative to the move sizes an ORB
targets, for any contract with more than a few days to expiry). **This
justification is weaker for NIFTY's weekly contracts near their own
expiry Tuesday than it was for candidate 15's monthly-only BankNifty
contracts** — flagged as a real difference, to be checked (does the
entry day fall inside expiry week?) rather than assumed away.

## Position sizing

1 lot per trade, both indices — simplest literal implementation, no
notional-matching exercise, same as candidate 15.

## Cost model

Reuse `core/breakout1010/costs.py`'s composed options cost function
(STT/exchange/stamp/SEBI/GST via `core/options/vrp/costs.py`'s time-varying
rates, F&O-specific, not cash-equity defaults) — applies to both indices
unchanged, since these are rate schedules, not index-specific mechanics.

**Slippage stress test (added 2026-07-28, before any backtest ran)**: this
candidate's cost-sensitivity risk is explicitly worse than candidate 15's
(see limitation #1, above — more round-trips/day against the same
synthetic-premium/spread blind spot). Every backtest run therefore
computes and reports **two** net results per index, not one:

1. **Clean**: the cost model exactly as specified above.
2. **Stressed**: the same cost model plus an additional 15bps-per-leg
   slippage penalty (midpoint of the reviewed 10-20bps range), applied to
   both the entry and exit leg of every trade.

Both numbers are reported side by side for both NIFTY and BankNifty — a
pass on Clean that fails on Stressed is itself a reportable finding (the
edge is an artifact of the synthetic pricing having no real spread), not a
result to average away or discard the less favorable of the two.

## Validation criterion / pass-fail bar

**Same bar used throughout this project**: `core/backtest/parser.py`'s
`has_positive_edge` — profit factor > 1.0 AND Sharpe > 0.5 — on the pooled
NET (post-cost) trade set, **computed and reported separately for NIFTY
and BankNifty, and separately for Clean and Stressed** (four numbers
total, never blended). **The Stressed result is the one that gates any
move toward live capital** — a Clean-only pass is not sufficient, given
this candidate's disclosed cost-sensitivity risk.

**Reported alongside each of the four numbers**: a per-year breakdown,
same discipline as every prior candidate, bounded by each index's
confirmed 5-minute depth window above.

## What would make this validation untrustworthy after the fact

- Changing the opening-range window (first 3 5m candles), the
  one-trade-per-day rule, the close-only breakout confirmation, the
  initial-stop placement, the 1-range-width trailing-arm trigger, the
  3-candle trailing lookback, the DTE floor, or the 25%-premium secondary
  stop, after seeing a weak or strong result.
- Reverting to 1-minute candles for either index individually (e.g. "NIFTY
  looked bad on 5m, try 1m instead") after seeing a weak result — the
  resolution switch was made once, for both indices, before any result
  existed; it is not a per-index lever to pull afterward.
- Pooling NIFTY and BankNifty into one number instead of reporting both
  independently.
- Reporting only the Clean cost result and omitting the Stressed
  (15bps-slippage) result, or treating a Clean-only pass as sufficient to
  move toward live capital.
- Treating a pass on this synthetic-premium backtest as sufficient to move
  to live capital without a follow-up feasibility check against real,
  current option-chain quotes (same requirement candidate 15 named and
  never got to exercise, since it failed first).
- Silently narrowing the backtest window to whatever the depth probe finds
  convenient, without recording the probe's actual finding here first.
- Adding entry filters (e.g. an indicator-confirmation layer) to this
  candidate's signal after a weak result, instead of treating a filtered
  variant as a distinct, freshly pre-registered candidate 19 that discloses
  it was built in response to 18's specific failure mode.
