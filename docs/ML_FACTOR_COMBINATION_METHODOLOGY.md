# ML Multi-Factor Stock Ranking — Methodology, Pre-Committed 2026-07-27 Before Any Result Exists

## Why this exists

Candidate 16 in this project's strategy search, and the first to depart from
the "one rule-based signal, sink or swim alone" pattern every prior
candidate followed. After candidate 15 ([[quantos_1010_breakout_status]])
closed — the 15th such candidate — the user reframed the project's
direction: this project hasn't produced 15 dead ends, it's produced ~10
independently-tested, cost-validated FACTOR PIPELINES that each failed as a
STANDALONE rule. This candidate combines several of them into one ML model
instead of requiring any single factor to carry a strategy alone.

**Do not edit this file after the backtest has run.** A wrong parameter is
a finding for a NEXT pre-registered run, not a retroactive edit here.

## The bar this candidate must clear — stricter than any prior one

This is a capital-tracked rotation strategy, evaluated the way S1 Dual
Momentum and S8-3 actually were — CAGR/Sharpe/max-drawdown on a real
simulated account (`core/rotation/equity_curve.py`), not the pooled-per-
trade `has_positive_edge` (PF>1.0, Sharpe>0.5) bar candidates 1-15 used.
That bar (CAGR>0%, Sharpe>0.5) is necessary but **not sufficient** here:
the live S8-3 rotation strategy already trades a single-factor (52-week
momentum) version of this exact idea, and its own survivorship-bias-
corrected verdict ([[quantos_s8_3_survivorship_fix_status]]) was a REAL
LOSS to both benchmarks (-15.6pts to Nifty500, -64.6pts to Nifty Alpha
50). A model that clears CAGR>0%/Sharpe>0.5 but doesn't beat that single-
factor baseline over the same held-out period isn't an improvement — it's
noise that happened to clear a low bar. **This candidate must beat, on the
held-out test period only: (1) CAGR>0% and Sharpe>0.5, (2) Nifty 500 buy-
and-hold, (3) Nifty Alpha 50 buy-and-hold, AND (4) the single-factor-
momentum baseline (`core/rotation/ranker.py`'s `rank_universe`, S8-3's own
live logic) run over the identical universe/dates/costs.** Failing to beat (4) specifically
is disqualifying regardless of (1)-(3), since (4) is what's actually
running today.

## Scope discipline — this is a backtest-only candidate

Nothing here touches the live S8-3 strategy or real capital. Even a clean
pass on every criterion above is not sufficient on its own to swap this
into live trading — that would be a separate, explicit decision, same
precedent as every "next step" disclosed-but-not-taken in this project's
prior methodology docs.

## Universe, cadence, and window

**Universe**: Nifty 500, matching S8-3's current (post-de-link) live
configuration — the strategy this could eventually inform, not S1 Dual
Momentum's narrower Nifty 200. Point-in-time membership via
`core/rotation/nifty500_reconstitution.py`'s `build_point_in_time_universe`/
`eligible_symbols_asof` — same survivorship-bias fix S8-3 itself already
required, applied from the start here rather than retrofitted.

**Rebalance cadence**: weekly, matching both S1 Dual Momentum's 168-weekly-
rebalance precedent and S8-3's live weekly systemd timer.

**Window**: **3 years**, matching this project's established rotation-
strategy convention (S1 Dual Momentum, S8-3's own default), ending at the
latest available session at run time. **Train/test split, fixed now, not
tuned after seeing results**: the first 24 months are the TRAIN set (used
for fitting only), the final 12 months are the TEST set (touched only
once, for the final reported result) — a genuine held-out period, unlike
several earlier candidates in this project that were criticized or paused
for being in-sample-only (e.g. [[quantos_momentum_turnover_ablation_status]]).

## Features — 4 for v1, all per-stock/cross-sectional (same grain)

Chosen from the factor-pipeline inventory taken 2026-07-27: only signals
with the SAME grain (one value per stock per rebalance date) are combined
into one flat feature row here. Index-level regime/vol-conditioning
(broadcasts one value to every stock that day, and its breadth component
has no historical backtest data source at all) and pair-level cointegration
z-scores (different instrument, futures not cash equity) are explicitly
OUT of scope for this v1 — different grain, would need a different
integration design (e.g. a market-level gate layered on top of this
model's output, not a feature inside it). PEAD earnings surprise is also
deferred — the underlying NSE XBRL filing fetch hasn't been re-confirmed
live recently ([[quantos_pead_earnings_feasibility]] found zero new filing
data on its last check) and isn't worth blocking v1 on.

1. **52-week RS momentum score** — `core/rotation/ranker.py`'s
   `value_as_of`/`rank_universe` machinery, reused unchanged. Already
   point-in-time-safe, no extraction needed.
2. **Dual-momentum composite score** — `core/rotation/dual_momentum.py`'s
   `ranked_eligible_symbols`/`build_indicators`. Already point-in-time-safe
   (its `_atr_at_entry` already dodges a same-day lookahead bug Fable
   caught in an earlier review — a good template, not a red flag). Reused
   unchanged.
3. **Mean-reversion signal** — `core/meanreversion/gutcheck.py`'s
   `compute_signals`/`rsi14`/`walk_forward_emas`, wrapped in a new
   `value_as_of(symbol, date)`-style function (`core/mlfactors/features.py`,
   see "Open items" below) rather than reused as-is (its current shape is a
   bool-crossing list aligned to a candle index, not a bisectable score).
   **`compute_signals` silently falls back to NIFTY 50's trend when a stock
   has no matching real NSE sectoral index** — this becomes an explicit
   `sector_mapped: bool` feature column, not a hidden imputation the model
   can't see.
4. **Days since last reconstitution event (added/removed)** —
   `core/rotation/nifty500_reconstitution.py`'s `EVENTS`, wrapped in a new
   lookup function. Real event coverage only starts 2023-09-29 (confirmed
   live 2026-07-27: 11 events, earliest 2023-09-29) — about 2 months into
   this backtest's 3-year window if it starts ~2023-07-27. Exposed via an
   explicit `reconstitution_data_known: bool` feature column (false before
   2023-09-29), same "disclose the gap, don't silently impute" principle as
   feature #3 — the model can learn to discount this feature when it's
   unknown rather than being fed a misleading default.

## Label — binary, top-quintile forward performer

Per the user's explicit choice (2026-07-27, over forward-return regression
and a full learning-to-rank objective): for each (symbol, rebalance date)
row, **label = 1 if that symbol's forward return to the NEXT rebalance date
ranks in the top 20% of the eligible universe that week, else 0.** Matches
the actual decision S8-3/this candidate makes (pick the best ~N stocks),
rather than optimizing for exact-return accuracy everywhere (regression) or
adding pairwise-ranking machinery this 4-feature v1 doesn't need.

Forward return is computed using `value_as_of` at the CURRENT rebalance
date and the NEXT rebalance date's price — no different from how every
prior candidate in this project computes forward returns, same
no-lookahead discipline (a row's label is only knowable once the next
rebalance date's price exists, and is never used as a feature for that
same row).

## Model — logistic regression only, no model-shopping

**One model, decided now: `sklearn.linear_model.LogisticRegression`**, L2-
regularized, standardized features. Not compared against a gradient-boosted-
tree alternative for this v1 — with only 4 features and one held-out test
period, trying multiple model classes and reporting whichever looks best
on the test set would itself be a form of the exact overfitting/data-
snooping trap this project's whole discipline exists to prevent. A future
candidate can pre-register a tree-based model AS ITS OWN hypothesis, with
its own held-out test period, if the linear model doesn't clear the bar
above — not as a same-run fallback chosen after seeing results.

**New dependency**: `scikit-learn` is not currently in `requirements.txt`
(confirmed live 2026-07-27 — only `pandas`/`numpy` are). Added as part of
this candidate's implementation; a standard, low-risk, widely-used library
for this use case, not a bespoke or exotic dependency.

**Hyperparameters** (regularization strength `C`, etc.): selected via
time-based cross-validation WITHIN the TRAIN set only (e.g. expanding-
window CV across the 24 train months), never touching the 12-month test
set. Fixed once selected, before the test-set evaluation ever runs.

## Backtest integration — a minimal, disclosed change to shared code

`core/rotation/equity_curve.py`'s `simulate_portfolio` currently hardcodes
`target_basket = rank_universe(symbol_series, today, top_n, eligible=eligible)`
at each rebalance — tightly coupled to the single-factor momentum ranker.
**Change**: add an optional `target_basket_fn` parameter (signature-
compatible with `rank_universe`), defaulting to `rank_universe` itself so
every EXISTING caller (S8-3, S1 Dual Momentum) is byte-for-byte unaffected.
This candidate passes its own function (the trained model's top-N picks by
predicted top-quintile probability, that week's eligible universe only) in
its place. This is the only planned change to shared/already-live code in
this candidate — everything else is new, additive modules.

Same `CostModel`, same `top_n`/`position_size` conventions, same
`universe_snapshots` point-in-time gating as S1 Dual Momentum's own
methodology, for direct comparability.

## Validation criterion / pass-fail bar

On the TEST period (final 12 months) only, using a FRESH capital-tracked
`simulate_portfolio` run starting at the test period's own first date (not
a slice of the full-window curve, so the comparison is a clean "what does
this look like starting from here," same semantics as candidate 15's
per-year breakdown):

1. **CAGR > 0% and Sharpe > 0.5 on the capital-tracked equity curve**
   (`core/rotation/equity_curve.py`'s own CAGR/Sharpe/max-drawdown
   methodology). Correction, caught before implementation began:
   `EquityCurveResult` has no `profit_factor` field — `has_positive_edge`
   (PF>1.0, Sharpe>0.5) is the POOLED PER-TRADE convention this project
   uses for point-count-driven backtests (candidates 1-15), a different
   metric family from the CAPITAL-TRACKED equity-curve convention S1 Dual
   Momentum and S8-3 actually established (see
   `quantos_three_strategy_proposals_review`: Strategy 1 failed its "own
   equity-curve Sharpe bar (0.45<0.5)" — that IS this project's real
   precedent bar for an equity-curve verdict, not a PF threshold). This
   candidate follows the equity-curve convention throughout, since it's
   evaluated the same way S1/S8-3 were.
2. Beats Nifty 500 buy-and-hold (`simulate_index_buy_and_hold`) over the
   same test period.
3. Beats Nifty Alpha 50 buy-and-hold over the same test period.
4. Beats the single-factor-momentum baseline (`rank_universe` run through
   the identical `simulate_portfolio` harness, same universe/dates/costs,
   its own fresh test-period-only run) over the same test period.

**All four required.** Reported alongside: TRAIN-period metrics (for
overfitting comparison — a test period that's dramatically worse than
train is itself a finding), and the model's feature coefficients/importances
(for interpretability — which factors is it actually leaning on).

## What would make this validation untrustworthy after the fact

- Touching the TEST period (final 12 months) more than once, or using it
  for any hyperparameter/feature decision.
- Switching model class after seeing the logistic regression underperform,
  within this same candidate/run.
- Changing the label definition (top-quintile threshold, forward-return
  horizon), the feature set, or the train/test split boundary after seeing
  a weak result.
- Reporting only CAGR/Sharpe while omitting the three benchmark
  comparisons — the whole point of this candidate is "better than what's
  already running," not "better than nothing."
- Treating a pass here as sufficient to swap into live S8-3 without a
  separate, explicit decision.
