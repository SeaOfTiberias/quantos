# Sector-Cointegrated Stock-Futures Pairs Trading — Methodology, Pre-Committed 2026-07-25 Before Any Result Exists

## Why this exists

The user pushed back on this project's pattern of reactively testing one
proposal at a time (see memory `quantos_three_strategy_proposals_review`,
`feedback_proactive_strategy_suggestions`) and asked for a proactive search
of the real world of algorithmic trading. A web research pass (2026-07-25,
same session) found most retail-facing "strategies" (bulk-deal following,
FII/DII flow-chasing) are unsourced blog claims with zero backtest evidence
— the same low-rigor category as the Iron-Condor CSV already reviewed and
debunked this project. Two categories had real academic backing specific to
Indian markets: **cointegration-based pairs trading** (multiple NSE-specific
papers, e.g. arxiv 2211.07080, Springer 10.1007/s10690-020-09317-1, both
finding same-sector pairs — Auto and Realty flagged strongest — cointegrate
and produce positive risk-adjusted returns), and **F&O expiry-day effects**
(a 22-year study, arxiv 2507.04859, queued as the next candidate after this
one). This doc covers pairs trading, the stronger-evidenced of the two —
this project's 12th strategy candidate.

**Do not edit this file after the validation has run.** A wrong parameter
is a finding for a NEXT pre-registered run, not a retroactive edit here.

## The structural constraint this design is built around

A classic pairs trade needs a genuine SHORT leg held for days to weeks,
until the spread reverts. Retail NSE cash-equity accounts cannot hold a
short position overnight in the cash segment — this is exactly the
constraint that killed the index-reconstitution candidate's short leg (see
memory `quantos_index_reconstitution_effect_feasibility`: "short leg has
0/149 F&O coverage + no legal overnight short in cash market"). **This
design uses single-stock FUTURES for both legs from the start**, not cash
equity — verified feasible before writing the rest of this doc, not
assumed:

- The already-cached raw NSE F&O bhavcopy zips (`data_cache/nse_bhavcopy/raw/`,
  739 files, built for VRP — see `core/options/vrp/bhavcopy.py`) contain
  `FinInstrmTp == "STF"` rows (single-stock futures) alongside the `IDO`/`STO`
  rows VRP and the option-skew work already used. Checked directly against
  `20260722.zip`: **210 distinct stock-futures underlyings**, 3 expiries
  each (current/next/far month), near-month volumes in the thousands per
  symbol for large/mid-caps (spot-checked ADANIENT 5382 contracts,
  ADANIPOWER 13161, ABB 3084 on that date) — real, liquid, no new download
  needed.
- New-format bhavcopy rows include `NewBrdLotQty` (lot size) directly per
  row — no separate lot-size lookup table needed.
- Going long/short a stock future overnight is a normal, legal F&O
  position (margin-based, no borrow requirement) — this removes the
  short-leg blocker entirely, unlike the reconstitution candidate.

## Universe — sector-tagged, futures-listed stocks only

**Step 1 — futures-listed base set:** every symbol with an `STF` row in the
most recent cached bhavcopy (re-checked at run time against the actual
latest cached file, not hardcoded — same convention `docs/VOL_SKEW_METHODOLOGY.md`
used). 210 as of 2026-07-22; this count drifts slowly as NSE adds/removes
F&O eligibility and is re-derived fresh each run, never hand-maintained.

**Step 2 — sector tag:** NSE's own sectoral index constituent CSVs, fetched
live from `https://nsearchives.nseindia.com/content/indices/ind_{name}list.csv`
— **confirmed programmatically fetchable 2026-07-25** (same host
`core/options/vrp/bhavcopy.py` already fetches from successfully; NOT the
`nseindia.com`/`niftyindices.com` hosts this project's earlier universe
files needed a manual download for). 13 sectors resolved live:
`niftybank`, `niftyit`, `niftypharma`, `niftyrealty`, `niftymetal`,
`niftyfmcg`, `niftyauto`, `niftyenergy`, `niftymedia`,
`niftyconsumerdurables`, `niftyoilgas`, `niftypsubank`, `niftyhealthcare`.
(`niftyfinservice` and `niftyprivatebank` 404'd under this URL pattern —
dropped, not substituted, since a wrong guessed URL silently returning an
unrelated 404 page would be worse than a known gap.)

**Step 3 — pair eligibility:** a stock enters the universe only if it has
an STF row AND appears in at least one of the 13 sector lists. Pairs are
formed **only within the same sector tag** — never cross-sector. If a
symbol appears in more than one sector list (a genuine multi-segment
conglomerate, per NSE's own tagging, not a researcher choice), it
participates in pairs within EACH list it appears in, undeduped.

This is a deliberate multiple-testing control, not just a nod to the
academic precedent: restricting to same-sector pairs keeps the total
candidate-pair count in the low hundreds rather than the ~19,900 possible
pairs across all 210 names, which matters for the ADF threshold below.

## Price series and the no-continuous-contract rule

**Near-month stock-futures daily `ClsPric`**, from the already-cached raw
bhavcopy, restricted to **2026-01-01 cutover-format dates only**
(`FinInstrmTp == "STF"` rows only exist in the new bhavcopy format,
confirmed by `core/options/vrp/bhavcopy.py`'s own `CUTOVER_DATE =
2024-01-01`) — same "one data source, not two stitched together" rule
`docs/VOL_SKEW_METHODOLOGY.md` already established for the equivalent
legacy-format gap. Window: **2024-01-01 through the latest cached bhavcopy
date** (~2.5 years, re-checked at run time).

**No back-adjusted continuous series is built.** A position is always in
the CURRENT near-month contract. If a pair's trading-window position is
still open **3 trading days before the near-month contract's expiry**
(same DTE convention `docs/VOL_SKEW_METHODOLOGY.md` used), it is
force-closed at that day's close regardless of z-score state — no roll,
no synthetic splice. This is the simplest, most auditable construction
available (same "fewest researcher degrees of freedom" precedent VRP set
choosing a strangle over a condor), at the cost of occasionally cutting a
trade short before it would have reverted; that cost is accepted and
disclosed here, not discovered after a weak result. A force-closed pair is
not automatically re-entered in the new front-month contract — it must
requalify in the next formation cycle.

This needs no live Fyers/broker token at all — same advantage
`docs/VOL_SKEW_METHODOLOGY.md` already flagged for reusing the cached
bhavcopy pipeline.

## Cointegration test — Engle-Granger, log prices

For each sector-restricted candidate pair (A, B) in a formation window:

1. OLS regress `log(close_A)` on `log(close_B)` (log prices — standard
   practice to avoid scale/heteroskedasticity issues, pre-registered
   choice, not tuned after seeing raw-price results look worse) to get
   hedge ratio β.
2. Residual spread: `spread_t = log(close_A,t) - β * log(close_B,t)`.
3. Augmented Dickey-Fuller test (`statsmodels.tsa.stattools.adfuller`,
   default lag selection) on the residual spread series.
4. **Pass bar: ADF p-value < 0.05.** A pair that fails is dropped from
   that formation window entirely — no retry with a different lag or
   trend specification.

**New dependency**: `statsmodels` is not currently in `requirements.txt` —
added by this work, not previously used anywhere in this project. Reused
for the ADF implementation rather than hand-rolling one, same "reuse a
well-tested library" precedent as `core/options/greeks.py`'s
bisection-not-Newton IV solver choice.

**Disclosed limitation, not fixed after seeing results:** no multiple-testing
correction (e.g. Benjamini-Hochberg) is applied across the sector-restricted
candidate set, which is expected to run to the low hundreds of pairs per
formation window. At p<0.05 with ~200-300 tests, a handful of pairs are
expected to pass by chance alone even under a true null. This is a known,
stated weakness of the p<0.05 threshold as used here, consistent with the
academic precedent found ("at least 90% significance" — i.e., an even
looser bar than this doc uses) — not a reason to retroactively tighten the
bar if the pooled result looks weak, but a reason to read the per-fold
breakdown (see Validation criterion) skeptically rather than trust the
pooled number alone.

## Walk-forward schedule — formation and trading are separate from the start

This is the one thing the momentum-turnover candidate (`quantos_momentum_turnover_ablation_status`)
got right only in a follow-up: Fable's standing criticism there was that
everything — the original result, the coverage-clean check, the half-split
— drew from the SAME single in-sample window. This design bakes the
formation/trading split in from the first run, not as a retrofit:

- **Formation window: 6 months.** Cointegration test (above) run once per
  formation window, using ONLY that window's daily closes.
- **Trading window: the 3 months immediately following formation.**
  Frozen β and frozen formation-period spread mean/std are used throughout
  — **no re-estimation during the trading window** (avoids lookahead: a
  hedge ratio re-estimated using trading-window data would leak future
  information into today's signal).
- **Step forward 3 months and repeat** across the full 2024-01-01 →
  latest-cached window. ~2.5 years of data yields roughly 8 non-overlapping
  quarterly trading windows, each preceded by its own fresh 6-month
  formation lookback (exact count/dates computed at run time from the
  actual cached date range, not hardcoded).
- **Honest sample-size caveat, stated up front per the momentum-ablation
  lesson:** 8 quarterly folds is itself a thin sample for judging
  stability across market regimes — reported explicitly, not glossed over.

## Entry / exit rules (trading window only)

- `z_t = (spread_t - formation_mean) / formation_std`, computed daily
  using trading-window prices against the FROZEN formation-window mean/std.
- **Entry**: `|z_t|` crosses above 2.0. If `z_t > +2.0`: short the spread
  (short A-leg future, long β-scaled B-leg future). If `z_t < -2.0`: long
  the spread (opposite legs).
- **Exit**, whichever comes first: `z_t` crosses back through 0.0 (mean
  reached), OR 20 trading days elapse since entry (stop chasing a spread
  that never reverts — same order-of-magnitude horizon as this project's
  other diagnostic horizons, e.g. PEAD's/reconstitution's), OR the
  force-close-before-expiry rule above triggers.
- One open position per pair at a time — no pyramiding or re-entry mid-trade.
- **Sizing**: dollar-neutral legs, sized off a fixed representative
  ₹100,000 notional per trade (same `NOTIONAL_PER_TRADE` convention as
  S8-3), rounded to the nearest whole lot on each leg (futures trade in
  fixed lot sizes — `NewBrdLotQty` from the bhavcopy row). No further
  adjustment for the resulting rounding slack between legs — disclosed,
  not corrected, same as every rounding choice this project has made
  rather than adding a tunable correction after the fact.

## Cost model — NEW, not a reuse of DELIVERY_COST_MODEL or the VRP options model

This trades F&O stock futures, not cash-equity delivery (`core/risk/costs.py`'s
`DELIVERY_COST_MODEL`, S8-3/S1's model) and not options premium (`core/options/vrp/costs.py`).
Neither existing model's shape fits: futures costs are a percentage of
FUTURES TURNOVER (price × lot size × lots), not premium, and STT applies
differently.

**Sourced, time-varying futures STT (sell side only), same schedule-table
pattern `core/options/vrp/costs.py` already uses for options STT**:
- 0.0125% until 2024-09-30
- 0.02% from 2024-10-01 (Budget 2024, effective 1 Oct 2024 — Business
  Standard / ICICI Direct coverage of the Finance Bill)
- 0.05% from 2026-04-01 (Budget 2026 hike — ICICI Direct coverage)

**Brokerage**: 0.03% of turnover per order, capped ₹20/order — same shape
as the equity model, still needs calibration against Fyers' actual F&O
brokerage calculator before trusting (not yet done — remains an open item
below, same "calibrated, not assumed" bar `core/risk/costs.py`'s own
docstring sets; unlike the two items below, this one needs a live
calculator/contract note, not a public rate table).

**Exchange transaction charge (RESOLVED, sourced 2026-07-25, not guessed)**:
**₹1.73/lakh of futures turnover (0.00173%), both legs**, the uniform rate
effective 2024-10-01 (Bajaj Broking's coverage of NSE's transaction-charge
circular, corroborated by a second source giving the same figure). Before
2024-10-01 NSE used a variable/slab rate up to ₹1.88/lakh — this backtest's
window starts 2024-01-01, so ~9 months fall before the rate change; per
`core/options/vrp/costs.py`'s own precedent for the exact same kind of gap
(pre-2024-10-01 options slab system), the post-2024-10-01 uniform rate is
applied across the whole window as a stated approximation, not a
reconstructed slab.

**Stamp duty (RESOLVED, sourced 2026-07-25)**: **0.002% on the futures buy
leg** — confirmed distinct from options' 0.003% and equity delivery's
0.003%, per the Finance Act 2019 instrument-category schedule.

**SEBI turnover fee**: ₹10/crore (0.0001%), same uniform rate used
everywhere else in this project.

**GST (time-varying, RESOLVED, sourced 2026-07-25 — a real nuance not
previously modeled anywhere in this project)**: 18% on (brokerage +
exchange) **before 2025-04-01**; 18% on (brokerage + exchange + SEBI)
**from 2025-04-01 onward** — SEBI turnover fees only started attracting
GST from that date. Every other cost model in this project (`core/risk/costs.py`,
`core/options/vrp/costs.py`) applies GST to SEBI unconditionally across
their whole windows; both of those backtests' windows sit entirely after
2025-04-01 so the simplification never mattered there, but this backtest's
window starts 2024-01-01 and spans the change, so it is modeled as a third
time-varying schedule (alongside the STT schedule above), not the older
models' constant assumption.

## Validation criterion / pass-fail bar

**Same bar used throughout this project**: `core/backtest/parser.py`'s
`has_positive_edge` — profit factor > 1.0 AND Sharpe > 0.5 — computed on
the POOLED trading-window trades only (formation windows generate no
trades), NET of the cost model above.

**Reported alongside the pooled number, not instead of it**: a per-fold
breakdown (each of the ~8 quarterly trading windows' own trade count,
PF, and Sharpe) — mirroring the half-split stability check Fable required
for the momentum candidate, except here it's built in from the first run
rather than a follow-up. A pooled pass driven by one or two lucky quarters
is a materially different finding than a pass that holds up fold-by-fold,
and both get reported.

## What would make this validation untrustworthy after the fact

- Changing the ADF p-value threshold (0.05), the 6-month/3-month
  formation/trading split, the z-score entry/exit bands (2.0 / 0.0), the
  20-trading-day max hold, or the log-price hedge-ratio construction after
  seeing a weak or strong result.
- Re-estimating β or the spread mean/std during a trading window instead
  of using the frozen formation-window values.
- Widening from same-sector-only to cross-sector pairs to chase a better
  number.
- Reporting only the pooled result while omitting a materially different
  per-fold breakdown.
- Applying a multiple-testing correction only after seeing that the
  uncorrected result looks weak (or skipping one that would have been
  applied had the result looked strong).
- Guessing the unverified futures exchange-transaction-charge or stamp
  duty rates rather than sourcing them before this backtest's cost model
  is finalized.
